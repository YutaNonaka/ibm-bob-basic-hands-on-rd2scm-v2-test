## 実装手順

1. `faq/faq-data.js` を作成する。
   * `FAQ_CATEGORIES`(id・表示名)と `FAQ_ITEMS`(id、category、question、answer)を定義する。
   * `answer` は「ブロック配列」で表現する。要素は段落(`{type:'p', text}`)または箇条書き(`{type:'ul', items:[...]}`)。
   * 太字・インラインコードは、テキスト中の `**太字**` と `` `コード` `` の簡易記法で表し、`script.js` が DOM 要素に変換する(`innerHTML` は使わない)。
   * `qa.md` の全17項目を、並び順どおりに日本語へ翻訳して登録する。
2. `faq/index.html` を作成する。
   * 検索入力(`type="search"`、ラベル付き)、タブ領域、件数表示(`aria-live="polite"`)、一覧コンテナ、空状態要素(初期は非表示)を配置する。
   * `faq-data.js`、`script.js` の順に読み込む。
3. `faq/styles.css` を作成する。
   * 白背景、グレー系文字、青系アクセント1色。最大幅約800px、中央寄せ。
   * 質問ボタンは高さ44px以上。`:focus-visible` のアウトラインを表示する。
   * タブは `flex-wrap` で折り返す。幅320pxで横スクロールが出ないこと。
   * 開閉は `hidden` 属性で制御し、開閉アイコン(▸/▾ 相当)を CSS で切り替える。
4. `faq/script.js` を作成する。
   * 状態: 選択カテゴリ、検索語。
   * 正規化関数: 前後空白を除去し、`toLowerCase` と `normalize('NFKC')` で大文字小文字・全角半角を吸収する。
   * 描画関数: 状態に応じて項目を絞り込み、「すべて」選択時はカテゴリ見出し付きで描画する。該当のないカテゴリ見出しは出さない。
   * アコーディオン: `button` に `aria-expanded` / `aria-controls` を設定し、クリックで回答パネルを開閉する(複数同時に開ける)。再描画時も開いている項目の状態を保持する。
   * 件数表示を「全17件中 N件を表示」で更新し、0件のとき空状態を表示して一覧を隠す。
   * 検索クリアボタンの動作を実装する。
   * 検索語・データは `textContent` / `createElement` のみで扱い、`innerHTML` は使用しない。
5. 検証計画に従って確認する。

## GUI実装

* 対象コンポーネント: 単一ページ。構成は ヘッダー / 検索ボックス+クリアボタン / カテゴリタブ(5つ、`button` + `aria-pressed`) / 件数表示 / FAQ一覧(カテゴリ見出し+アコーディオン) / 空状態 / フッター。
* スタイル: `faq/styles.css` に集約。CSS変数で色・余白を管理。システムフォント(日本語対応のフォントスタック)、行間1.6。
* 状態管理: `script.js` 内のモジュール変数(選択カテゴリ、検索語、開いている項目idの集合)。永続化(localStorage 等)は行わない。
* 画面遷移: なし。
* レスポンシブ対応: 幅320px〜PC。タブ折り返し、余白の縮小、タップ領域44px以上。メディアクエリは最小限(狭幅での余白・文字サイズ調整程度)。

## テストの追加・更新

* 自動テストは追加しない(仕様書で手動確認中心と合意済みの範囲)。ビルド環境を持たない静的サイトのため。
* 代わりに、データ検証用の確認として、Node.js が利用できる場合は `faq-data.js` を読み込み、件数(全17件、カテゴリ別 5/8/2/2)と必須項目の欠落がないことを一時的なコマンドで確認する(ファイルは追加しない)。

## 検証計画

* 仕様書「確認方法」1〜7に従って確認する。
* この環境でブラウザ操作ができない場合は、`node --check` による構文確認と、データ件数の確認までを実施し、画面表示・レスポンシブ・キーボード操作は未確認として明示し、ユーザーによる確認を依頼する。
* `qa.md` の各項目と `faq-data.js` を突き合わせ、欠落・重複がないことを確認する。
* 外部URL・外部ライブラリの参照がないことを `grep` で確認する。
